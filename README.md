Проект посвящен исследованию и практическому применению новейшей архитектуры **YOLOv11** для автоматического обнаружения государственных регистрационных знаков (ГРЗ) в видеопотоке. Работа выполнена в рамках учебной практики по разработке нейросетей.

## Предмет изучения

Основная сложность при работе с детекцией в видеопотоке - необходимость баланса между точностью и скоростью. Ошибка пропуска объекта (False Negative) критична в системах контроля доступа, но высокая задержка обработки делает систему непригодной для реального времени.

В данном проекте исследованы четыре архитектуры YOLOv11 (nano, small, medium, large) на предмет:
- Точности детекции (mAP, Precision, Recall)
- Скорости инференса (FPS, время обработки кадра)
- Потребления вычислительных ресурсов (VRAM, время обучения)

## Основные возможности:
* **SOTA архитектура:** Использование YOLOv11 обеспечивает высокую точность и скорость обработки кадров.
* **Инференс на видео:** Обработка видеофайлов с автоматическим наложением Bounding Boxes на распознанные объекты.
* **Адаптация под железо:** Код поддерживает вычисления на GPU (NVIDIA CUDA / AMD ROCm), что критично для задач реального времени.


## Краткое описание разработки

### 1. Подготовка данных
* **Источник данных**: Датасет "Russia car plate" с платформы Roboflow.
* **Объем выборки**: 
  - Train: 600 изображений
  - Valid: 200 изображений  
  - Test: 47 изображений
* **Формат**: YOLO (готов к использованию без дополнительной предобработки).
* **Аугментации**: Встроенные в YOLO при обучении.

### 2. Исследование архитектур
* **Модели**: YOLOv11n, YOLOv11s, YOLOv11m, YOLOv11l.
* **Гиперпараметры**:
  - Эпохи: 5 (для быстрого сравнительного анализа)
  - Batch size: 16
  - Размер изображения: 640x640
* **Метрики оценки**:
  - mAP50, mAP50-95 (точность)
  - Precision, Recall
  - Время обучения, использование GPU памяти

### 3. Оптимизация для реального времени
* **Выбор архитектуры**: Сравнение nano, small, medium, large версий.
* **Метрики скорости**: FPS, время инференса на кадр.

### 4. Демонстрация
* Инференс на тестовом видеоролике с автомобилями.
* Визуализация детектированных номеров с bounding boxes.

## Результаты экспериментов

### Сравнение архитектур YOLOv11

| Модель | mAP50 | mAP50-95 | Precision | Recall | Время обучения (мин) | VRAM (ГБ) |
|--------|-------|----------|-----------|--------|---------------------|-----------|
| **YOLOv11n** | **0.967** | 0.661 | 0.962 | 0.963 | 1.7 | 2.1 |
| YOLOv11s | 0.960 | 0.657 | 0.958 | 0.949 | 1.6 | 4.0 |
| YOLOv11m | **0.969** | 0.665 | 0.967 | 0.962 | 3.2 | 8.0 |
| YOLOv11l | 0.902 | 0.619 | 0.904 | 0.898 | 4.3 | 10.4 |

### Ключевые выводы

1. **Лучший баланс**: YOLOv11n — оптимальный выбор для реального времени
   - mAP50: 0.967 (сопоставим с medium)
   - VRAM: всего 2.1 ГБ (в 4-5 раз меньше large)
   - Время обучения: 1.7 мин (в 2.5 раза быстрее large)

2. **Проблема крупных моделей**: YOLOv11l не успевает сойтись за 5 эпох
   - Уступает nano по точности (mAP50: 0.902 vs 0.967)
   - Требует в 5 раз больше памяти

3. **Лучше всего для применения в условиях ограниченных ресурсов**:
   - Для FPS > 25: YOLOv11n с разрешением ≤ 640px
   - Для максимальной точности: YOLOv11m (если ресурсы позволяют)
   - Квантование в FP16 для дополнительного ускорения
